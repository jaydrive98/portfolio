HubSpot → BigQuery
Data Pipeline

A pipeline that copies the entire HubSpot CRM — every contact, deal, company, campaign and email event — into a BigQuery warehouse on a schedule, so the whole business can analyse its CRM data properly. The clever part: it runs on infrastructure that only exists while the job is running.

The problem

A CRM full of data you can't really analyse

HubSpot is where the business lives — 320k+ contacts (each with over a thousand fields), deals, companies, marketing campaigns and a firehose of email events. It's a brilliant CRM, but it's a poor place to do serious analysis. You can't easily join it to event or finance data, run heavy queries, or build the kind of historical, cross-team reporting leadership wanted.

The answer is a proper data warehouse. This pipeline mirrors HubSpot's whole data model into BigQuery on a schedule — turning a locked-in CRM into an open, queryable dataset that powers dashboards, machine learning, and joins with every other system. The design goal on top of that: do it without paying for a data platform that sits idle 23 hours a day.

The core idea

Infrastructure that builds and destroys itself

A managed Airflow environment (Cloud Composer) is powerful but expensive to leave running around the clock. So instead of keeping one alive, a Cloud Workflow creates a fresh environment at the start of each run, lets it do its work, and then snapshots and deletes it at the end.

The handshake is the neat bit: the Workflow writes a private "call me when you're done" URL into Cloud Storage and waits. Inside the freshly-built environment, a master DAG I call the Overlord starts automatically, runs every extraction job, waits for them all to finish — then reads that URL and posts back to tell the Workflow it's safe to tear everything down. Crucially, that teardown signal fires even if some jobs failed, so a bad run can never leave expensive infrastructure running.

Each HubSpot object has its own extraction job: contacts (320k+ rows, 1,000+ fields each), companies, deals, leads, campaigns, products, line items, forms and lists. On top of that sit eleven dedicated email-event streams, five activity types (emails, calls, meetings, tasks and notes), and four master association "junction" tables — for deals, contacts, companies and leads — that each fan out into ten or more tables of their own.

The master DAG adjusts what runs based on the calendar: the lighter objects refresh every run, while the heaviest one — a full contacts sync — only runs on a longer cycle to keep each run fast and cheap.

Engineering highlights

The interesting bits

Ephemeral, cost-optimised infra

A Cloud Workflow creates → runs → snapshots → destroys the Airflow environment every cycle. You get all of managed Airflow's power without paying for it to sit idle between runs.

Self-orchestrating master DAG

The "Overlord" auto-starts on a fresh environment, cleans up any stale runs, triggers every child job, waits for completion, and signals teardown — reliably, even when individual jobs fail.

Two clean ETL patterns

Simple objects use extract → NDJSON in Cloud Storage → load to BigQuery. Append-only streams (email events, associations) add a staging table and an idempotent MERGE into the main table.

Incremental watermarking

The forms pipeline tracks the last submission time per form in a BigQuery watermark table, so each run pulls only what's new instead of re-fetching everything.

API-friendly extraction

Every HubSpot call uses exponential backoff and retries to respect rate limits, so a busy API or a transient error slows a job down rather than breaking the run.

Dynamic, calendar-aware scheduling

The job list changes with the date — heavy full-syncs run on a bi-weekly / bi-monthly cadence while everything else runs every cycle, balancing freshness against cost and runtime.

The result

From an 8-hour Friday to a self-running warehouse

This one grew out of necessity. Teams started with zero visibility into this data. My first fix was a manual export of just contacts and lists — which quickly swallowed my entire Friday, eight hours of pulling, cleaning and visualising by hand every week. As the exports outgrew a spreadsheet, they needed a database; and once there was a database, the whole thing begged to be automated.

The business now has its complete HubSpot history sitting in BigQuery — refreshed automatically, ready to join with event, finance and marketing data, and running for a fraction of the cost of an always-on data platform. It's the foundation the executive Looker Studio dashboards and the revenue-forecasting models are built on. And I got my Fridays back.
